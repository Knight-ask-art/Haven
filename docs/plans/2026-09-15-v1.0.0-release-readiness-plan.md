# Plan

本计划把 Haven（栖阅）从当前 `origin/main@7d0758e4253abfacdde4024847a7a5b5a4ef9173` 推进到可以正式交付用户的 `v1.0.0`，目标不是把已有 beta 重新命名，而是完成产品闭环、真实 Windows/WebView2 验收、数据升级保护和签名发布流程。现有 `v0.1.0-beta.1`（发布提交 `ff568d449665694d424f05178d488d7318eea231`）仍是旧的 prerelease，不能作为当前主线的正式安装包；任何候选版本都必须在自己的精确提交上重新通过全部门禁。

## Release baseline

- 代码基线：以 `origin/main@7d0758e` 为准；当前本地 `main` 仍是旧历史，不能用本地旧分支代替发布基线，也不能通过强制同步破坏本地历史。
- 产品形态：Windows 桌面端、Tauri 2、React 19、Rust + SQLite、本地优先；浏览器 Preview、Mock、单元测试和历史门禁记录都不能替代真实桌面验收。
- 发布原则：先锁定支持范围，再补齐四类内容的可用闭环，最后在干净候选提交上生成、签名、安装、升级和回滚验证材料。
- 证据规则：每一项都区分“代码已实现”“当前提交自动化通过”“真实 Windows/WebView2 已验证”“可发布”；没有当前候选提交的 Fresh Gate 或真实运行证据，不得标记为完成。

## Scope

- In:
  - Windows 正式用户版本的核心本地能力：媒体播放、漫画阅读、TXT/Markdown/EPUB/PDF/HTML 阅读、CBZ/图片目录漫画、收藏、进度、历史、书签/划线、下载/离线和受控资源生命周期。
  - 影视、漫画、小说/图书和报刊资料四类内容的生产级阅读或播放闭环，包括错误、空数据、来源失败、重试、关闭、重开和数据恢复。
  - 漫画 Work/Edition/ChapterSourceRef/Subject 进度连续性、页面变化后的最佳努力迁移、迁移证据、撤销、目标进度保护和冲突交互。
  - 报刊资料的独立期刊、ISSN、卷、期、发行日期、文章归属、正文状态和专用 Provider 产品路径，而不只是通用 Article/Document 投影。
  - 数据库迁移、备份恢复、beta 到 stable 升级、签名安装包、Updater、Release notes、支持边界和发布后回滚流程。
  - Rust、Tauri、Wire、前端、Provider、网络安全边界和真实 Windows/WebView2 的发布门禁。
- Out:
  - 移动端、账号体系、云同步、跨设备同步、OCR、AI、翻译和未经过 Foundation/风险评审的新平台能力。
  - 把任意元数据搜索结果宣传为可阅读正文或可播放内容；没有正文/媒体资源能力的 Provider 只能显示为元数据候选。
  - 未经独立验收的新来源大扩张、任意第三方 URL 直连、绕过受控 Session 的资源读取，以及与 V1.0.0 无关的视觉重构。
  - 以“测试全绿”替代真实桌面、网络、安装包、升级、长时间播放和数据恢复证据。

## Release blocking policy

- 任一 P0/P1 功能、数据完整性、安全边界、安装升级或回滚门禁失败，阻止 `v1.0.0` 发布。
- 不得发布已知会丢失进度、书签、划线、下载状态或用户数据库的版本；数据库迁移失败必须可恢复，不能只依赖重新安装。
- 不得发布无法验证签名、完整性、升级来源或卸载/重装行为的安装包；更新检查在签名发布前必须保持安全不可用，而不是静默安装未签名文件。
- P2 缺口只有在不影响已宣传的支持范围、不造成数据/安全风险，并且在 Release notes 中明确限制和后续计划时，才可以不阻塞首个稳定版本。
- 原始运行日志、诊断包、真实用户数据和凭据不进入公开仓库；公开仓库只提交脱敏的验收摘要、用户文档和 Release notes。

## Definition of done

- 四类内容都有真实 Windows/WebView2 的打开、关闭、重开、错误恢复证据；影视可播放，漫画可阅读并完成迁移操作闭环，小说/图书可按承诺格式阅读，报刊可按期刊树浏览到文章正文。
- 真实 Provider 的成功、无结果、限流、超时、部分失败、正文缺失和重试状态都能被用户理解；元数据候选不会伪装成可阅读/可播放内容。
- 进度、书签、Marker、下载、来源配置和期刊数据在升级、重启、离线和恢复场景下保持一致；没有已知 P0/P1 数据丢失或权限绕过风险。
- 最终候选提交的 Rust/Tauri/前端/Wire/安全/CodeQL/安装包门禁全部通过；所有报告引用的是同一候选 SHA，而不是历史分支或旧 beta 的结果。
- Windows 安装包可验证来源和签名，beta 到 stable 的升级和失败恢复有实测记录，用户文档、变更记录、支持范围和已知限制与实际能力一致。
